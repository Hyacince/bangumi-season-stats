# Bangumi 季度番剧统计（Tampermonkey 油猴脚本）

统计某个 Bangumi 用户在 **「看过」和「在看」** 收藏中的 **TV 动画**，
按**季度**（依据条目标签里的 `xxxx年x月`，如 `2025年1月`、`2026年7月`）汇总数量，
只保留 **1 / 4 / 7 / 10 月**四个季度；开播时间特殊的月份（如 2月、11月）归入其所属季度，
最后在页面上以**柱状图**直观展示每个季度看了多少部动画，并可查看/导出每个季度的作品明细。

文件：`bangumi-season-stats.user.js`

---

## 统计口径（按你的需求实现）

1. 只统计用户收藏状态为 **看过（collect）** 和 **在看（do）** 的条目；
2. 只统计其中 **动画（subject_type=2）**，且平台类型为 **TV** 的条目；
   **WEB、剧场版、OVA/OAD、其它平台一律不统计**；
3. 条目的“详情页标签”里必须包含 **`xxxx年x月`** 格式的季度标签（例如 `2025年1月`、`2026年7月`），
   标签决定该动画归属哪个季度；**没有该格式标签的条目不统计**；
4. **只保留 1 / 4 / 7 / 10 月四个季度**：开播时间特殊的月份按所属季度归并——
   1-3月 → 1月季（冬）、4-6月 → 4月季（春）、7-9月 → 7月季（夏）、10-12月 → 10月季（秋）；
5. 「看过」「在看」两个列表中的条目按条目 ID 去重合并统计（同一动画只计一次）；
6. 整个过程**只读**，不会修改你的任何收藏数据。

> 判断依据：条目平台（TV）与标签均来自该条目的公开详情数据（api.bgm.tv/v0/subjects/{id}）。
> 例如 [bgm.tv/subject/602733](https://bgm.tv/subject/602733)（标签 `2026年7月`）、
> [bgm.tv/subject/486347](https://bgm.tv/subject/486347)（标签 `2025年1月`）这类条目会被正确归类；
> 标签为 `2021年11月` 的年番会归入 `2021年10月` 季。

## 安装

1. 安装 Tampermonkey（Chrome/Edge：[Chrome 商店](https://chromewebstore.google.com/detail/dhdgffkkebhmkfjojejmpbldmpobfkfo)，Firefox：[AMO](https://addons.mozilla.org/zh-CN/firefox/addon/tampermonkey/)）；
2. 任选一种方式安装脚本：
   - 打开 Tampermonkey 管理面板 → “新建脚本” → 删除默认内容 → 把 `bangumi-season-stats.user.js` 的**全部内容**粘贴进去 → `Ctrl+S` 保存；
   - 或在管理面板 → “工具/Utilities” → “导入”中选择该 `.user.js` 文件；
3. 打开 **https://bgm.tv** 并登录你的账号；
4. 进入**个人主页**（`/user/{你的用户名}`），在昵称下方、**自我介绍下面的“加入”日期那一栏**会多出一个
   **蓝色胶囊「季度番剧统计」＋ 右侧“启动”** 的入口（与右侧 Badge 栏样式统一），点击即可弹出统计面板。
   **入口仅在本用户主页页面上显示**，其它页面不会出现任何按钮。

## 使用

1. **用户名无需手动输入**：在本用户主页点击入口时，脚本会自动把当前主页的用户名填入面板
   （也即统计你自己）；如需统计别人，直接在面板里改成对方的用户名即可 ——
   手动改过的用户名**不会被自动填入覆盖**，可放心使用；
2. 勾选要统计的状态（**看过**、**在看**，默认都勾）；
3. “请求间隔”默认 `1100ms`（每抓一条详情休息约 1.1 秒，避免触发 api.bgm.tv 限流；
   若频繁出现“获取失败/429”，可调大到 `2000~3000ms`）；
4. （可选）如果收藏里有 **R18 条目**：在下方“访问令牌”框填入你在
   [bgm.tv/dev/app](https://bgm.tv/dev/app) 创建的个人访问令牌 —— R18 条目只对**注册满两个月**
   的账号可见，且 API 请求需带认证，否则会被记为“API获取失败（404）”；
5. 点击 **▶ 开始统计**：
   - 先打开 `/anime/list/{用户名}` 读取页面上的「看过/在看」页签**真实链接**，自动兼容
     `?type=collect`（查询式）与 `/collect`（路径式）两种 URL 格式，并逐页翻取该状态下的**全部条目**
     （同源抓取，无需 Token）；抓到数量会与页签标注数量（如“看过(800)”）对比，差异大时在日志给出警告；
   - 再对每条去重条目调用公开接口获取平台类型与标签；
   - 右上角显示进度条与日志；
6. 完成后展示：
   - **汇总**：去重条目数、计入统计的动画数、季度数、以及被排除的数量（WEB/剧场版/OVA/OAD/其它平台/无季度标签/API失败）；
   - **柱状图**：按年份分组、每月一个柱子（仅 1/4/7/10 月四季；**固定绘图区、柱子统一从底部基准线向上生长**），柱子颜色区分冬(1月)/春(4月)/夏(7月)/秋(10月)，柱顶显示数量，悬停可预览该季作品，**点击柱子**跳转到下方该季明细；
   - **季度作品明细**：下拉选择季度，列出该季每部动画（标题可点进条目页，显示原名、平台、状态）；
   - 支持 **导出 CSV**、**复制文本摘要**、**清除条目缓存**，以及 API 失败时的 **导出失败清单**（含条目 ID 与失败原因，便于核对 R18/已删除条目）。

> 耗时参考：条目详情按“请求间隔”逐个抓取，约 900 条 ≈ 17 分钟（间隔 1100ms）。
> 建议第一次跑之前留足时间，或先把间隔调小到 800ms（若大量出现 429 再调大）。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面没有悬浮按钮 | 入口只在本用户主页显示（“加入”日期那一栏，蓝色胶囊“季度番剧统计”＋“启动”）。请打开 `/user/{用户名}` 查看；**其它页面刻意不显示任何入口**。脚本只匹配 `bgm.tv / bangumi.tv / chii.in` |
| 提示“没有找到任何条目” | 检查用户名是否写错；确认该用户（或你自己的）动画收藏列表是公开可访问的；先打开一次自己的收藏页确认路径为 `/anime/list/{用户名}` |
| 很多条显示“API获取失败（404）” | **很可能就是 R18 条目**：R18 内容只对注册满两个月、且带认证的请求开放，匿名访问 API 会返回 404（已合并/删除的条目也会 404）。处理：在 [bgm.tv/dev/app](https://bgm.tv/dev/app) 创建个人访问令牌填入面板后重跑；或用“导出失败清单”核对具体条目 ID 是否 R18 |
| 很多条显示“API获取失败（429/网络）” | 多半被限流或网络波动。把“请求间隔”调大（2000ms 以上）后重跑；失败的条目下次运行会自动重试，也可点“清除条目缓存”强制重抓 |
| 数字和你预期不符 | WEB/剧场版/OVA/SP/其它平台不计入；“看过/在看”外的收藏（想看/搁置/抛弃）不计入；条目没有 `xxxx年x月` 格式标签不计入；开播月份特殊的会归并到所属季度（如 2月→1月季、11月→10月季）。这些都会被列在“未计入”里 |
| 结果里混入了“想看/搁置/抛弃”的条目，或总数远小于收藏数 | 这是 **v1.0.x 的已知问题**（旧版列表 URL 参数被站点忽略，只抓到了第一页“全部”）。请升级到 **v1.1.0+** 后重跑：新版会自动识别页签真实链接并翻取全部条目；若日志仍提示“抓到数量与页面标注差异较大”，把用户名和该提示截图反馈 |
| 柱子看起来顶部不齐/不在同一基线 | 升级到 v1.1.0+：绘图区改为固定高度，所有柱子统一**底部对齐** |
| 想重新统计最新数据 | 条目标签缓存 7 天，点“清除条目缓存”可立即全部重抓 |
| 中途想停 | 点 ⏹ 停止，会以已抓取到的部分给出统计 |

> 提示：`bgm.tv` 与 `bangumi.tv` 是两个不同域名，条目缓存按域名分别存放，切换域名使用时会重新抓取一次（属正常现象）。

## 技术说明

- 收藏列表：同源抓取页面 HTML。先读取 `/anime/list/{user}` 上的“看过/在看”页签链接（自动兼容 `?type=collect` 与 `/collect` 两种格式），再按 `&page=N` 逐页翻取，仅提取条目 ID，不读取任何私密数据；
- 条目详情：`GET https://api.bgm.tv/v0/subjects/{id}`，从 `platform` 字段判定 TV/WEB/剧场版/OVA（仅 TV 计入统计），从 `tags` 字段匹配 `xxxx年x月` 季度标签，并把特殊月份归并到 1/4/7/10 月所属季度；默认匿名请求即可读取普通条目，**R18 条目需在面板填入个人访问令牌**（注册满两个月的账号）后以 `Authorization: Bearer` 认证读取，否则记为 API 404 失败；
- 运行时每个域名下对条目详情做 localStorage 缓存（正常结果 7 天、失败结果 2 小时后自动重试），重复运行秒级完成；
- 请求自动限速并对 429/5xx 退避重试（最多 4 次），不会写任何收藏数据。
