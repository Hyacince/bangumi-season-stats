# Bangumi 追番统计（Tampermonkey 油猴脚本）

统计某个 Bangumi 用户在 **「看过」和「在看」** 收藏中的数据，提供两种模式（面板顶部可切换）：

1. **季度番剧统计**：仅 **TV 动画**，按**季度**（依据条目标签里的 `xxxx年x月`，如 `2025年1月`）汇总数量，
   只保留 **1 / 4 / 7 / 10 月**四个季度，特殊开播月份归入所属季度；柱状图展示每季看了多少部。
2. **追番 / 补番统计**：包含 **TV / WEB / OVA / 剧场版 / 其它** 全部动画类型（结果页可勾选显示哪些类型），
   按 **收藏年份** 汇总 **追番**（收藏年份 ≤ 条目完结年份）与 **补番**（晚于完结年份）的数量与比例。

统计结果会**自动保存在本浏览器**：之后打开个人主页点“启动”即可直接看到上次结果，只有手动点“开始统计”才会更新。

文件：`bangumi-season-stats.user.js`

## 统计口径

### 通用

1. 只统计收藏状态为 **看过（collect）** 和 **在看（do）** 的条目，按条目 ID 去重（同一动画只计一次）；
2. 整个过程**只读**，不会修改你的任何收藏数据。

### 季度番剧统计

1. 只统计 **动画（subject_type=2）** 且平台为 **TV** 的条目（**WEB、剧场版、OVA/OAD、其它平台不计入**）；
2. 条目“详情页标签”里必须包含 **`xxxx年x月`** 格式的季度标签（如 `2025年1月`、`2026年7月`），
   标签决定归属季度；**没有该格式标签的条目不统计**；
3. **只保留 1 / 4 / 7 / 10 月四个季度**：特殊月份按所属季度归并——
   1-3月 → 1月季（冬）、4-6月 → 4月季（春）、7-9月 → 7月季（夏）、10-12月 → 10月季（秋）。

> 例如 [bgm.tv/subject/602733](https://bgm.tv/subject/602733)（标签 `2026年7月`）、
> [bgm.tv/subject/486347](https://bgm.tv/subject/486347)（标签 `2025年1月`）会被正确归类；
> 标签为 `2021年11月` 的年番会归入 `2021年10月` 季。

### 追番 / 补番统计

1. 统计 **全部动画类型**（TV / WEB / OVA / 剧场版 / 其它），结果页顶部提供**类型多选**筛选（可同时选多个）；
2. **完结年份**：优先取条目信息里的「放送结束 / 完结」日期；缺失时退回季度标签年份（再退回开播年份），
   表格中会标 `*` 表示估算；
3. **收藏年份**：填入访问令牌时取官方收藏接口的收藏时间（最可靠）；未填令牌时尽力从收藏列表页行内日期解析；
4. 判定：**收藏年份 ≤ 完结年份 → 追番**；**收藏年份 > 完结年份 → 补番**
   （即“同年开播时收藏”以及“未开播先收藏”都算追番）；
5. 缺收藏时间或缺完结时间的条目计入 **“无法判断”**，不参与比例计算，面板会分别显示缺多少。

## 安装

1. 安装 Tampermonkey（Chrome/Edge：[Chrome 商店](https://chromewebstore.google.com/detail/dhdgffkkebhmkfjojejmpbldmpobfkfo)，Firefox：[AMO](https://addons.mozilla.org/zh-CN/firefox/addon/tampermonkey/)）；
2. 任选一种方式安装脚本：
   - 打开 Tampermonkey 管理面板 → “新建脚本” → 删除默认内容 → 把 `bangumi-season-stats.user.js` 的**全部内容**粘贴进去 → `Ctrl+S` 保存；
   - 或在管理面板 → “工具/Utilities” → “导入”中选择该 `.user.js` 文件；
3. 打开 **https://bgm.tv** 并登录你的账号；
4. 进入**个人主页**（`/user/{你的用户名}`），在昵称下方、**自我介绍下面的“加入”日期那一栏**会多出一个
   **蓝色胶囊「季度番剧统计」＋ 右侧“启动”** 的入口（与右侧 Badge 栏样式统一），点击即可弹出统计面板。
   **入口仅在本用户主页页面上显示**，其它页面不会出现任何按钮。

## 使用

1. **用户名无需手动输入**：在本用户主页点击入口时，脚本会自动把当前主页的用户名填入面板
   （也即统计你自己）；如需统计别人，直接在面板里改成对方的用户名即可 ——
   手动改过的用户名**不会被自动填入覆盖**，可放心使用；
2. 在面板顶部选择模式：**季度番剧统计** / **追番 / 补番统计**（选择会记住）；
3. 勾选要统计的状态（**看过**、**在看**，默认都勾）；
4. “请求间隔”默认 `1100ms`（每抓一条详情休息约 1.1 秒，避免触发 api.bgm.tv 限流；
   若频繁出现“获取失败/429”，可调大到 `2000~3000ms`）；
5. **（建议填）访问令牌**：在 [bgm.tv/dev/app](https://bgm.tv/dev/app) 创建个人访问令牌填入面板。
   - 追/补统计需要它来读取**收藏时间**；
   - R18 条目也只对**注册满两个月**且带认证的请求开放（匿名会 404）；
6. 点击 **▶ 开始统计**：
   - 先打开 `/anime/list/{用户名}` 读取页面上的「看过/在看」页签**真实链接**，自动兼容
     `?type=collect`（查询式）与 `/collect`（路径式）两种 URL 格式，并逐页翻取该状态下的**全部条目**
     （同源抓取，无需 Token）；抓到数量会与页签标注数量（如“看过(800)”）对比，差异大时在日志给出警告；
   - 再对每条去重条目调用公开接口获取平台类型、标签与完结日期；追/补模式还会读取收藏时间；
   - 右上角显示进度条与日志；
7. 完成后展示：
   - **季度模式**：汇总（去重条目数 / 计入统计数 / 季度数 / 未计入明细）、按年分组的柱状图（1/4/7/10 月四季，柱子底部对齐、点击查看该季明细）、季度作品明细；
   - **追/补模式**：可多选的**类型筛选**（TV / WEB / OVA / 剧场版 / 其它，带数量）、追番/补番数量与占比、每年**堆叠柱状图**（蓝=追番、橙=补番）、年度汇总表、年度作品明细；
   - 两者都支持 **导出 CSV**、**复制文本摘要**、**清除已保存结果**、**清除条目缓存**，以及 API 失败时的 **导出失败清单**。

> 结果持久化：统计完成后结果保存在浏览器 localStorage（两种模式各存一份）。
> 刷新页面、切换页面、重开浏览器后，打开主页点“启动”即可直接看到上次结果；点 **▶ 开始统计** 才会更新数据，
> 点 **🧹 清除已保存结果** 可清空。

> 耗时参考：条目详情按“请求间隔”逐个抓取，约 900 条 ≈ 17 分钟（间隔 1100ms）。
> 升级到 v1.5.0 后缓存键变更，**第一次运行会重新抓取全部详情**，之后就快了。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面没有悬浮按钮 | 入口只在本用户主页显示（“加入”日期那一栏，蓝色胶囊“季度番剧统计”＋“启动”）。请打开 `/user/{用户名}` 查看；**其它页面刻意不显示任何入口**。脚本只匹配 `bgm.tv / bangumi.tv / chii.in` |
| 提示“没有找到任何条目” | 检查用户名是否写错；确认该用户（或你自己的）动画收藏列表是公开可访问的；先打开一次自己的收藏页确认路径为 `/anime/list/{用户名}` |
| 很多条显示“API获取失败（404）” | **很可能就是 R18 条目**：R18 内容只对注册满两个月、且带认证的请求开放，匿名访问 API 会返回 404（已合并/删除的条目也会 404）。处理：在 [bgm.tv/dev/app](https://bgm.tv/dev/app) 创建个人访问令牌填入面板后重跑；或用“导出失败清单”核对具体条目 ID 是否 R18 |
| 很多条显示“API获取失败（429/网络）” | 多半被限流或网络波动。把“请求间隔”调大（2000ms 以上）后重跑；失败的条目下次运行会自动重试，也可点“清除条目缓存”强制重抓 |
| 数字和你预期不符（季度模式） | WEB/剧场版/OVA/SP/其它平台不计入；“看过/在看”外的收藏（想看/搁置/抛弃）不计入；条目没有 `xxxx年x月` 格式标签不计入；开播月份特殊的会归并到所属季度（如 2月→1月季、11月→10月季）。这些都会被列在“未计入”里 |
| 追/补统计里很多“无法判断” | 缺**收藏时间**：请填访问令牌（官方收藏接口），否则脚本只能尽力解析列表页日期；缺**完结时间**：条目信息里没有「放送结束/完结」，会退回季度/开播年份估算（表格中标 `*`） |
| 追/补比例看起来不对 | 收藏时间优先用接口的 `created_at`，没有则用 `updated_at`（最后修改时间）——很久前看过但最近改过评分的条目可能被算到修改那年，属数据源限制 |
| 打开面板看不到上次结果 | 结果按域名保存在浏览器 localStorage：换域名（`bgm.tv` ↔ `bangumi.tv`）、清理浏览器数据、无痕窗口都会丢失，需重新统计一次 |
| 想看/搁置/抛弃的条目混入 / 总数远小于收藏数 | 这是 **v1.0.x 的已知问题**（旧版列表 URL 参数被站点忽略）。请用最新版重跑：会自动识别页签真实链接并按用户校验，必要时还会提示跳转错误 |
| 柱子看起来顶部不齐/不在同一基线 | 升级到 v1.1.0+：绘图区改为固定高度，所有柱子统一**底部对齐** |
| 想重新统计最新数据 | 条目标签缓存 7 天，点“清除条目缓存”可立即全部重抓 |
| 中途想停 | 点 ⏹ 停止，会以已抓取到的部分给出统计 |

> 提示：`bgm.tv` 与 `bangumi.tv` 是两个不同域名，条目缓存按域名分别存放，切换域名使用时会重新抓取一次（属正常现象）。

## 技术说明

- 收藏列表：同源抓取页面 HTML。先读取 `/anime/list/{user}` 上的“看过/在看”页签链接（仅接受属于目标用户的链接，自动兼容 `?type=collect` 与 `/collect` 两种格式），再按 `&page=N` 逐页翻取，仅提取条目 ID，不读取任何私密数据；
- 条目详情：`GET https://api.bgm.tv/v0/subjects/{id}`，从 `platform` 字段归类 TV/WEB/OVA/剧场版/其它（季度模式只取 TV），从 `tags` 字段匹配 `xxxx年x月` 季度标签，从 `infobox` 解析「放送结束/完结」得到完结年份；默认匿名请求即可读取普通条目，**R18 条目需在面板填入个人访问令牌**（注册满两个月的账号）后以 `Authorization: Bearer` 认证读取，否则记为 API 404 失败；
- 收藏时间（追/补模式）：`GET https://api.bgm.tv/v0/users/{username}/collections?subject_type=2&type=2|3`（需访问令牌），取 `created_at`（无则 `updated_at`）；未填令牌时回退解析收藏列表页行内日期；
- 结果持久化：统计完成后写入 localStorage 快照（`bgmSeasonStats.snapshot.v1`，两种模式各一份），打开面板时直接渲染，不重新抓取；
- 条目详情另有 localStorage 缓存（正常结果 7 天、失败结果 2 小时后自动重试），重复运行秒级完成；
- 请求自动限速并对 429/5xx 退避重试（最多 4 次），不会写任何收藏数据。
